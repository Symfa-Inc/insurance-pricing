# REVIEW: Insurance Pricing demo

Delivered: `../demo-insurance-pricing.mp4` (63.2 s, 1920x1080, 30 fps, H.264 High yuv420p, AAC LC 48 kHz stereo,
11.6 MB), `../poster.png` (t = 3.0 s, lossless snapshot).

## Creative calls
- Storyline A, "One applicant, one what-if" (see `../STORYLINES.md`); B ("the number first") and C ("six inputs")
  not built.
- One continuous take inside the real page. Chapter transition = the app's emerald header bar (14 px) sweeping
  left to right, drawing a #fafafa sheet, then sweeping again to uncover the product (3 cards + end card, all on
  beats). The only other transition is the blur swap from poster to the first chapter line on the same sheet.
- No caption strip. Words on screen: 3 chapter lines (<= 5 words, 112 px Geist 600, 1.8-2.0 s readable) and 7
  callouts (30 px on screen) anchored to the exact element, each 1.7-2.2 s.
- UI = DOM rebuild of the production build: its own Tailwind CSS, the captured markup, the real `/predict`
  responses. Backend :8017 and `next build` + `next start -p 3017` with `NEXT_PUBLIC_API_BASE_URL` / `CORS_ORIGINS`
  from the environment (no code edits; production build so the Next dev badge never exists). Capture viewport
  1920x1080. All servers stopped.
- Native `<select>` popups are drawn as a white zinc menu (a headless capture cannot show the OS popup); every
  other control uses the app's own states (focus ring, disabled 0.4, "Estimating" spinner, pending card,
  fade-in-up 0.4 s / 100 ms stagger, tooltip).
- What-if: the real app clears the results and shows the pending card between estimates. The film shows that
  real pending card on the first estimate; on the second it dims the results for 1.2 s while the button shows
  "Estimating", then morphs to the new run (price counts, bars swing, bullets rewrite) so the change is visible.
- AI text: an OpenAI key was present in the environment (never printed). 6 real runs per scenario
  (`assets/data/ai-runs/`), checked against the SHAP numbers on screen. Rejected: yes-1 ("$3,963 more than
  baseline", real gap $11,962), no-2 ("$515" for sex+region, real net +$87), no-3 (says the rest nudged the
  estimate down; it went up), plus the two runs the live UI happened to show during capture ("+$246"/"+$301"
  for the remaining features; real +$148/+$87). Used: yes-3 and no-5, whose every number matches the chart.
- Persona chosen so the row order is identical in both runs (smoker, bmi, age, sex, region, children), which lets
  the bars morph in place instead of reshuffling.

## Measured

  (product UI text at its real size and the real disabled Estimate button at opacity 0.4; reading happens
  through 30 px callouts and 112 px lines), `line_unread` (the second interpretation's long bullets and the
  tooltip: shown as product, the callout carries the point), `escaped_container` / `panel_out_of_canvas` /
  `container_overflow` (the camera zoom by design), `composition_file_too_large` (generated by
  `tools/build-app.mjs`).
- Layout vs live app: rebuilt page measured in a browser (`tools/measure.js` -> `assets/data/geom-recreation.json`)
  against the live capture (`assets/data/capture-dom.json`): inputs, selects, button, price, badge 0.0 px off
  after replicating the page's 15 px `scrollbar-gutter`. All cursor targets and callout anchors come from the
  measured file.
- Jitter: 7 held regions (chapter line, callouts, SHAP header, price, end card), 20-25 consecutive frames each:
  mean abs diff 0.00 on every pair. Zoom peaks (2.2-2.6x) inspected at full resolution: glyph edges crisp,
  no 1x-raster upscale (no `will-change`, `force3D:false`, blur filters cleared to `none` after each blur-in).
- Audio (rendered file): -15.7 LUFS integrated, LRA 1.7 LU, peak -3.1 dBFS, no clipping; music from 0.08 s;
  digital silence (-91 dB) from 62.37 s to 63.2 s. Clicks/keys/whooshes verified present by subtracting the bed
  (residual -31 to -34 dB RMS at each hit). Measured, not heard.
- Music: Google Lyria RealTime, 3 candidates at 100 BPM. A and B showed bright bands at 14-20 kHz in the
  spectrogram (A also clipped at +0.4 dBFS); C (lo-fi rhodes, bass, brushes) was clean and measured exactly
  100.00 BPM, so it was used: trimmed 0.08 s so beats land on multiples of 0.6 s, low-pass 15 kHz, -3 dB at
  110 Hz, loudnorm -15.5 LUFS / -1.5 dBTP, 2.4 s (one bar) fade from 60.0 s. Final mix spectrogram checked:
  no narrow-band tones.

## Fixed during review
- Tailwind's emoji fallbacks (`"Apple Color Emoji"`) made the renderer embed a 183 MB system font and every
  render worker timed out -> stripped from the app CSS at build.
- GSAP parses numeric-looking `textContent` ("+8602" became "8602", "30." would become "30") -> sign in its own
  span, typed values as one span per character.
- Dropdown menus sat outside the page root and fell back to Times -> Geist set on the menu.
- Second interpretation list was 12 px low (an absolutely positioned `ul` kept its `mt-3` after the first list's
  margin collapsed) -> `margin-top: 0`; both lists measure 259.5 px, so the card no longer jumps.
- Framing: the first zoom cut the page title and empty space dominated; the Feature Impact shot cut the
  tooltip and a line of text; the context shot left the bottom 40% empty while the page was still short ->
  every framing re-derived from measured edges (form 2.6x, price 2.2x, chart 2.55x, interpretation 2.57x,
  context 1.25x following the page as it grows).
- Callout "Was +$8,602, now -$9,056" overlapped the chart header -> anchored to the value instead.
- End-card mark was visible before its wipe (fromTo without immediate render) -> explicit initial clip.
- Cursor drop-shadow path read as a double edge at 2.6x -> CSS drop-shadow.

## Weakest shot / with more time
- 5.4-10.2 s (typing): at 2.6x the form sits right of centre and the left third of the frame is empty ground;
  the page is a 1024 px column in a 1920 px window, so a tighter, centred crop would expose the idle empty state.
- The second estimate morphs instead of showing the app's pending card again (see above).
- With more time: let a viewer see the result cards' own staggered fade a beat longer, and try a portrait cut.

## v3 (owner: poster underline too close) -> `../demo-insurance-pricing-v3.mp4` (v1, v2 kept)

61.0 s, same specs as v2, 9.4 MB. `poster.png` updated (t = 3.0 s). Only the underlines changed.

**Root cause.** Two separately hard-coded underline rules, both offset in px from the bottom of the word's inline-block,
whose height is the line-height (1.04em), not the glyphs: the poster's `#in-ul` used `bottom: 6px; height: 8px` at
104 px, which put the bar 3-11 px below the baseline, while Geist's "y" descends 15.6 px (0.150em), so the bar crossed
the descender; the cards' `.c?-ul` / `#in-lul` used `bottom: -14px; height: 10px` at 112 px.

**Measured on full-res frames** (rows of #00d294 bar vs lowest #009767 ink of the accent word):
- v2 poster "why.": bar 520-527 (8 px), descender ink to 531 -> overlap, bar 12 px above the descender's end.
- v2 cards "applicant", "price?", "quits": bar 10 px, gap 6 px.
- v3, all four (poster 2.2/3.0 s, 5.2, 22.2/22.6, 38.2 s): bar 10 px, gap 8 px, 0 text rows inside or below the bar.

**Fix.** One rule, `src/accent.css` (`.acc-u` / `.acc-bar`), copied into intro and both cards by
`tools/sync-accent.mjs` (run after `tools/build-cards.mjs`): the bar's top is computed from the font metrics
(baseline = (line-height - 1.3)/2 + 1.005 em, deepest descender 0.162em) + 6 px, 10 px thick. The end card has no
underline (unchanged). `hyperframes check` unchanged from v2 (the kept disabled-button contrast error, warnings as listed).

## v4 (owner: sharpness / encode quality) -> `../demo-insurance-pricing-v4.mp4` (v1-v3 kept)

Same content and timing as v3 (1830 frames, 61.0 s; SSIM v3 vs v4 0.9997). 12.6 MB, video 1.46 Mbps, AAC 192 kbps.

**Softness root-cause check (source side): nothing found.** No `will-change` or 3D transform anywhere (camera, cards,
Tailwind CSS); `gsap.config({ force3D: false })` in every composition, so the camera stays a 2D matrix and Chrome paints
DOM/SVG at the zoomed scale (the lossless frames show 1-px glyph edges at 2.3-2.6x, not a 1x raster stretched). Every
blur-in ends at `filter: none`; blur only remains on elements that are leaving (opacity 0 or off-frame).
**Encode side: the softness was the encoder.** Rendered a lossless PNG sequence, then
`ffmpeg -framerate 30 -i frame_%06d.png -i audio.m4a -c:v libx264 -preset slow -crf 6 -profile:v high -pix_fmt yuv420p
-r 30 -c:a copy -movflags +faststart` (the mixer's AAC 192k stream copied, not re-encoded).
Per-frame PSNR-Y against the lossless frames: v3 worst 48.9 dB / 5th percentile 53.2; CRF 16 slow was worse than v3
(worst 45.6, p5 51.7), CRF 12 49.4/54.9, CRF 10 51.3/57.0, CRF 8 52.9/58.7, **CRF 6 55.3/60.7 (used)**. The worst frames
are camera moves (31.0 s, 16.3 s): at 400% crops v3 shows smeared, blotchy ground around the OPENAI badge and soft
bullet text mid-move; v4 matches the lossless frame. Bitrate stays low because the film is flat UI with long holds.
